# Carrier architecture and checkpoint identity

This guide describes the source model used by the matched-adaptation study (six fitting seeds per method, 18 fits total) and the three-budget study. It does not describe the historical context-conditioned model. All paths below are relative to the project root. These are local artifacts, not a claim of a publicly released or independently reproduced training package.

**Current evidence status:** architecture and checkpoint identity do not establish simulator validity. The affected performance comparisons are on hold following the initialization audit; see [evidence status](../EVIDENCE_HOLD_20260913.md). The stored results and weights remain available for provenance checks.

## Architecture

The state is `[q(5), qvel(5), object_xy(2), object_vxy(2)]`. The action, diagnosed lock mask, and lock angles each have five coordinates. Each of five joint nodes receives six scalars: position, velocity, action, mask, lock angle, and normalized chain depth (`0, .25, .5, .75, 1`). Parameters are shared across joint nodes.

| Component | Layers and operation | Parameters |
|---|---|---:|
| Joint encoder | 6 → 136 → 136, SiLU after each linear layer | 19,584 |
| Message network | Concatenate node and sum of immediate chain neighbors; 272 → 136 → 136, SiLU after first linear layer | 55,760 |
| Spatial update | GRUCell(136,136), two message/update rounds with shared weights | 111,792 |
| Temporal update | GRUCell(136,136); initial recurrent state zero | 111,792 |
| Robot output | 136 → 136 → 2, SiLU hidden activation; additive joint position/velocity increments | 18,906 |
| Object output | Mean-pool the five next robot hidden states, stop gradient, concatenate four current object coordinates; 140 → 136 → 4 with SiLU; additive object increment | 19,724 |
| Geometric object residual | 12 → 16 → 4 with Tanh; final layer initialized to zero for new fits | 276 |

The full source state dictionary has 28 tensors and 337,834 parameters. Its no-residual carrier has the same stored architecture with the geometric head zeroed; that head is frozen in the carrier fits. The geometric model trains the object head and its newly initialized geometric head. The global alternative replaces that head with a 12 → 10 → 14 Tanh network (284 parameters), trains the object head plus global head, and retains frozen robot-backbone weights. The global head may change robot outputs despite the frozen backbone.

The primary configuration uses one robot expert, no robot input from object state, no separate object encoder, and the compact pooled robot-to-object bridge. Analytic projection enforces the diagnosed locked angle and zero locked velocity/command. The robot and object outputs use learned additive increments, not a separate position integration rule. The geometric descriptor, contact gates and candidate distributions are specified in the manuscript.

The exact 12-scalar descriptor order is: previous pusher XY (2), projected next pusher XY (2), next-minus-previous pusher XY (2), projected next pusher XY minus current object XY (2), current object XY velocity (2), contact gate at previous joint positions (1), and contact gate at projected next joint positions (1). Both gates use the current object position. The assembled descriptor is detached before the residual head. `contact_geometry.py` contains the forward-kinematic constants, two pusher capsule geometries, box dimensions and sample points that define those gates.

`carrier-specification.json` records every effective constructor argument, all tensor shapes, component counts and source identities. It was generated by loading the saved tensors strictly into the CPU constructor; this checks shape compatibility, not predictive performance or independent reproduction. No forward pass was executed.

## Source-to-fit mapping

1. `runs/icra_primary_decision_full_w10_128eval_strict_v2/seed27/model.pt` is the trained primary source. Its file SHA-256 is `7bf6888fb07bd3c52d42bb4816c0e27a5ce1aaba2ded20b5b09b1f8f8b71896e`. It is included in `foundation-checkpoints.zip`; the archive name does not imply training from scratch or exclude prior object adaptation.
2. `scripts/audit_ipwm_targeted_advantage.py:final_models` copies that model and zeros the geometric head to construct the carrier. It also loads global and nominal checkpoints as helper dependencies; those are not the weights used to initialize the common object head.
3. `scripts/ipwm_scale_train.py:build` copies that carrier for each fit. IPWM resets its geometric hidden layer and zeros its last layer. The global model copies common carrier tensors into its own constructor and starts its global head with a zero final layer. Common trained object parameters are reused and then updated in every method.
4. The six-fit models are under `runs/ipwm_scale_goal_20260911/training/{method}/seed{seed}`. Their original selection is governed by `training-protocol.json`; they are included in `adapted-checkpoints.zip`.
5. The separate three-budget study is under `runs/ipwm_data_budget_probe`. `protocol.json`, `selections.json`, and `results.json` identify its 27 fits and complete evaluations. Its source is the same earlier primary checkpoint, not the six-fit study's 50,000-trajectory adapted models. Its reported budgets exclude all source-model training and development data.

## Exact implementation route

| File | Role |
|---|---|
| `config/experiment/icra_primary_d2d4_decision_development_3seed_v1.yaml` | Primary options and earlier adaptation recipe |
| `src/robotarm/models/topology_graph_world_model.py:TopologyGraphConfig` | Five joints, four object coordinates, two message rounds; width overridden to 136 |
| `src/robotarm/models/block_triangular_dpwm.py:BlockTriangularDPWM` | Constructor and robot/object transitions |
| `src/robotarm/models/topology_surgery.py:TopologySurgery` | State/action projections |
| `src/robotarm/models/contact_geometry.py` | Pusher forward kinematics, capsule and box geometry, and sampled contact gates |
| `src/robotarm/models/selective_intervention_rollout.py` | Separate rollout states and returned-state composition |
| `scripts/ipwm_scale_train.py:build` | Current fit initialization and trainable parameter selection |
| `work/experiment_revision/data_budget/driver.py` | Frozen additional-data subsets, optimization/selection and evaluation protocol |

Only constructor-supported keys from the primary YAML are passed into `BlockTriangularDPWM`. For example, training-stage options in that YAML are not constructor switches. The resolved configuration in `carrier-specification.json` avoids that ambiguity.

## Coverage

This specification closes architecture and initialization ambiguities. It does not itself supply every historical dataset, transitive software dependency or a verified from-scratch recipe. Source training/development accounting is documented separately in `source-training-provenance.md`.
